# Changesets Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `release-it` with Changesets so the version bump lands via a PR and `npm publish` runs only after it merges — structurally eliminating the npm/git desync that has been breaking releases.

**Architecture:** `changesets/action` runs on push to `main`. With pending changesets it opens a "Version Packages" PR (bumps `package.json`, writes `CHANGELOG.md`); when none remain it runs `changeset publish` (npm via OIDC + provenance, git tag, GitHub release, inline docs dispatch). Mirrors `LottieFiles/dotlottie-web`, adapted to Yarn + npm-only.

**Tech Stack:** Yarn 3.6.1 (Berry), `@changesets/cli`, `@changesets/changelog-github`, GitHub Actions, npm OIDC trusted publishing.

**Spec:** `docs/superpowers/specs/2026-06-01-changesets-migration-design.md`

## Task 4: Rewrite the Release workflow

**Files:**
- Rewrite: `.github/workflows/release.yml`

- [ ] **Step 1: Replace `.github/workflows/release.yml` with:**

```yaml
name: Release

on:
  push:
    branches: [main]
  workflow_dispatch:

concurrency:
  group: release
  cancel-in-progress: false

permissions: {}

jobs:
  validate:
    name: Validate
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup
        uses: ./.github/actions/setup

      - name: Lint files
        run: yarn lint

      - name: Typecheck files
        run: yarn typecheck

      - name: Build package
        run: yarn prepare

      - name: Run tests
        run: yarn test

  release:
    name: Release
    needs: validate
    runs-on: ubuntu-latest
    if: github.repository == 'LottieFiles/dotlottie-react-native'
    permissions:
      contents: write
      id-token: write
      pull-requests: write
    outputs:
      published: ${{ steps.changesets.outputs.published }}
      publishedPackages: ${{ steps.changesets.outputs.publishedPackages }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false

      - name: Setup
        uses: ./.github/actions/setup

      - name: Create Release PR or Publish
        id: changesets
        uses: changesets/action@63a615b9cd06ba9a3e6d13796c7fbcb080a60a0b # v1.8.0
        with:
          version: yarn release:version
          publish: yarn release:publish
          commit: "chore: release"
          title: "chore: release"
          createGithubReleases: true
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_CONFIG_PROVENANCE: "true"

      - name: Notify docs-content
        if: steps.changesets.outputs.published == 'true'
        env:
          GH_TOKEN: ${{ secrets.DOCS_CONTENT_SYNC_TOKEN }}
          REPO_TOKEN: ${{ github.token }}
          PUBLISHED: ${{ steps.changesets.outputs.publishedPackages }}
          SENDER: ${{ github.actor }}
          SOURCE_REPO: ${{ github.repository }}
        run: |
          # Release lookups use the repo token (REPO_TOKEN); only the final
          # docs-content dispatch uses the default GH_TOKEN (DOCS_CONTENT_SYNC_TOKEN).
          echo "$PUBLISHED" | jq -c '.[]' | while read -r PKG; do
            VERSION=$(jq -r '.version' <<<"$PKG")
            # Single-package repo → changesets tags as v<version>. Fall back to <name>@<version> just in case.
            NAME=$(jq -r '.name' <<<"$PKG")
            TAG="v${VERSION}"
            if ! GH_TOKEN="$REPO_TOKEN" gh release view "$TAG" --repo "$SOURCE_REPO" >/dev/null 2>&1; then
              TAG="${NAME}@${VERSION}"
            fi

            REL=$(GH_TOKEN="$REPO_TOKEN" gh release view "$TAG" --repo "$SOURCE_REPO" --json name,body,url)

            jq -n \
              --arg source_repo "$SOURCE_REPO" \
              --arg source_package "" \
              --arg release_tag "$TAG" \
              --argjson rel "$REL" \
              --arg sender "$SENDER" \
              '{event_type:"dotlottie-docs-eval", client_payload:{source_repo:$source_repo, source_package:$source_package, release_tag:$release_tag, release_name:$rel.name, release_body:$rel.body, release_url:$rel.url, sender:$sender}}' \
              > payload.json

            gh api --method POST "/repos/LottieFiles/docs-content/dispatches" --input payload.json
          done
```

> Notes for the implementer:
> - `validate` runs on **both** `push` and `workflow_dispatch` (no event `if:`), so `release` (`needs: validate`) is never skipped by a skipped dependency — this differs from web on purpose.
> - `changesets/action` is SHA-pinned (web's v1.8.0). `actions/checkout` stays at `@v4` to match this repo's existing convention (`ci.yml`, the setup action).
> - The docs step runs on a `push` trigger, so `github.event.release` is unavailable — the release is looked up by tag via `gh release view`. **Confirm the tag scheme on the first real release** (single-package Changesets uses `v<version>`); the fallback handles `<name>@<version>`.
